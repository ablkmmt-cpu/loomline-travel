## 二、差距清单（按类别）

优先级说明：**P0** = 上线前必须；**P1** = 上线后 1~2 月内；**P2** = 中期规划。

### A. 项目规范（P0，纯文档，1 小时可补）

| # | 缺失项 | 为什么需要 | 建议 |
|---|---|---|---|
| A1 | **README.md** | 新人/AI 代理接手项目没有入口：目录结构、本地运行、维护流程、部署方式 | 写一份：目录说明 + `node tools/stamp.mjs` 用法 + 页面清单 + 联系方式 |
| A2 | 代码/提交规范 | 提交信息随意，历史不可追溯 | 约定 commit 前缀（feat/fix/chore/docs）与一行式描述；现有 2 个提交示例化 |
| A3 | 404 页面 | 静态站删除/改路径后死链会给用户"网站坏了"的印象，伤信任 | 新建 `404.html`（品牌样式 + 回首页 + WhatsApp 兜底） |

### B. 版本与协作（P1）

| # | 缺失项 | 为什么需要 | 建议 |
|---|---|---|---|
| B1 | 远程仓库（GitHub 私有） | 无异地备份；无法多设备/多人生存 | 建 Private repo，推基线；之后每步提交可随时 push |
| B2 | 发布版本号（tag） | 现在只有 2 个无版本号提交，无法说清"线上是哪个版本" | 以 `v0.1.0`（骨架）起步，此后每次上线打 tag + 简短说明 |
| B3 | CHANGELOG | 客户/团队看不到网站演进 | 用 tag 描述即可，可不单独建文件（P2 再评估） |

### C. 部署上线（P0，上线前必须定）

| # | 缺失项 | 为什么需要 | 建议 |
|---|---|---|---|
| C1 | **托管方案** | 目前没有部署到任何线上环境（只在本地） | 推荐 Netlify/Vercel 静态托管（免费、HTTPS、CDN 自动）；或自有服务器；需你确认 |
| C2 | **域名与 HTTPS** | 提示词里域名是占位符；无 HTTPS 无法投放广告/被索引 | 确定正式域名后：DNS 接入 + 托管平台自动签发 HTTPS |
| C3 | CI/CD 流水线 | 现在改完代码要靠手动上传 | 托管平台连接 git 仓库后自动部署（GitHub → Netlify/Vercel 一条命令级配置）；`.github/workflows` 或平台配置二选一 |
| C4 | robots.txt / sitemap.xml | 已在 SEO 批次提示词里 | 随 SEO 批次执行（`previews/codex-seo-infrastructure.md`） |
| C5 | 环境区分 | 无 staging 环境，改坏了只能线上回滚 | 静态站可用"分支预览"（Netlify/Vercel 自带），不强制建多环境 |

### D. 质量保障（P1）

| # | 缺失项 | 为什么需要 | 建议 |
|---|---|---|---|
| D1 | stamp.mjs 自动化测试 | 打标脚本是全站维护命脉，改坏会批量污染 20 页 | 加 3 个单测：字节一致性断言、幂等性、标记完整性（`node --test`，无需装依赖） |
| D2 | HTML 结构校验 | 20 页手写 HTML，坏标签难发现 | 在 CI 里跑 `html-validate`（或先用现有 Python 标签平衡检查脚本固化进 tools/） |
| D3 | 坏链检测 | 页面间互链多，路径改动易产生死链 | 上线前跑一次链接爬虫（如 `lychee`/`wget --spider`），之后进 CI |
| D4 | 代码格式化 | 多人/AI 修改后风格漂移 | Prettier 配置 + 一次全站格式化（可选，优先级低） |
| D5 | 性能基线 | 大图未转 WebP，无 Core Web Vitals 基准 | 上线后用 PageSpeed 测一次存档；大图优化属第三层 P2-6 |
